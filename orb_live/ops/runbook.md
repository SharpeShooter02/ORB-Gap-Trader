# ORB Live — Operator Runbook

## 1. Daily Pre-Flight (before 08:30 ET)

1. **Check health endpoint**
   ```
   curl http://localhost:8080/health
   ```
   Expected: `200 OK`

2. **Review yesterday's daily summary** (auto-generated by `daily_rollup`):
   ```
   ls data/archive/$(date +%Y)/
   ```

3. **Verify broker account equity** matches expectations:
   ```
   curl http://localhost:8080/status | python -m json.tool
   ```

4. **Confirm the session process is running**:
   ```
   systemctl status orb-live   # or: pgrep -f orb_live.runner.main
   ```

---

## 2. Starting / Restarting a Session

### Normal start
```bash
cd /opt/orb-live
source .venv/bin/activate
nohup python -m orb_live.runner.main >> data/logs/session.log 2>&1 &
```

### After a crash mid-session
The state_store (SQLite) persists open positions across restarts.  The
runner re-reads all open positions from `state_store.all_open_positions()`
on startup, so a clean restart is always safe.

```bash
systemctl restart orb-live
```

Monitor startup with:
```bash
tail -f data/logs/session.log
```

## 3. Monitoring During RTH

### Endpoints
| URL                         | Purpose                                    |
|-----------------------------|--------------------------------------------|
| `GET /health`               | 200=OK; 503=issue (body explains why)      |
| `GET /status`               | Full JSON session snapshot                 |
| `GET /positions`            | Open positions list                        |
| `GET /metrics`              | Prometheus text (scrape with Grafana)      |

### Key status fields
- `session_state`: `pre_market` → `orb_window` → `trade_active` → `eod_exit`
- `ws_token_age_minutes`: auto-refresh fires at 720 min (12h)
- `last_bar_received_ts`: should update every minute during RTH
- `session_kill_active`: True means kill-switch triggered; review logs
- `open_positions`: should decrease to 0 by 16:00 ET (13:00 on half-days)

### Alert levels
- **INFO**: session lifecycle events (opt-in via `ALERT_INFO_OPT_IN=true`)
- **WARN**: degraded conditions (stale bars, partial fills, high reconnects)
- **CRITICAL**: kill-switch, metric drift, WS failure, position stuck

## 4. Half-Day Sessions

Half-days (e.g. July 3, day after Thanksgiving) automatically use 13:00 ET
as the EOD close.  The session runner queries `MarketClock.effective_close()`
at EOD time — no operator action required.

Verify detection before market open:
```
curl http://localhost:8080/status | python -m json.tool | grep -E "is_half|close"
```
Expected on half-day:
```json
"is_half_day": true,
"todays_close_et": "13:00"
```

## 5. WebSocket Reconnect Procedures

### Automatic reconnect (normal)
The WebSocket reconnects automatically with exponential backoff (1s → 30s).
After 5 minutes of continuous failures, the system enters **degraded mode**
and switches to 1-minute REST polling, logging a CRITICAL alert.

### Manual reconnect (if needed)
```bash
python -m orb_live.scripts.force_ws_reconnect --reconnect
```
This writes a sentinel file that triggers reconnect within 60 seconds.

### Verify reconnect succeeded
```
curl http://localhost:8080/status | python -m json.tool | grep ws_token
```
`ws_token_age_minutes` resets to near 0 after a successful reconnect.

### Token refresh (automatic, every 12h)
The `BarRouter._token_refresh_watcher` forces a reconnect every 12 hours.
No operator action needed unless `CRITICAL: ws_token_refresh_failed` appears.

## 6. Emergency Procedures

### Kill all open positions immediately
```python
# Interactive: attach to running process or run separately
from orb_live.core.state_store import StateStore
from orb_live.config.live_config import load_live_config
from orb_live.data.ib_client import build_client_from_env
from orb_live.execution.position_manager import LivePositionManager

cfg    = load_live_config()
store  = StateStore(cfg.db_path)
broker = build_client_from_env(paper=False)
broker.connect()
# Then: broker.close_all_positions() or close each via broker.submit_market_order(...)
```

The session runner also has a kill-switch triggered by:
- Session loss exceeding `session_kill_loss_pct` (default 3%)
- Writing `.kill` file to the working directory (checked every bar)

### Restore from backup after data loss
```bash
# Stop the live process first
systemctl stop orb-live

# List available backups
python -m orb_live.scripts.restore_from_backup --list

# Restore
python -m orb_live.scripts.restore_from_backup --date 2025-04-01

# Restart
systemctl start orb-live
```

### Force backup right now
```bash
python -m orb_live.scripts.backup_state_store
```

## 7. Quarterly Maintenance

Run on the first trading day of each quarter (January, April, July, October):

```bash
python -m orb_live.ops.quarterly_calibration full
```

This runs:
1. **ADV baseline recompute** — flags illiquid symbols (CRITICAL < 50% of 1yr ADV)
2. **Metric drift detection** — z-score check vs historical mean ± 2σ
3. **Universe audit** — reports added/removed symbols since quarter start

Results are saved to `data/archive/{YYYY}/adv_baseline.parquet` and
`data/archive/{YYYY}/Q{n}_universe_audit.md`.

Individual jobs:
```bash
python -m orb_live.ops.quarterly_calibration adv
python -m orb_live.ops.quarterly_calibration drift
python -m orb_live.ops.quarterly_calibration universe
```

## 8. Log Management

Logs rotate automatically:
- **0–30 days**: live `.log` files in `data/logs/`
- **30–90 days**: compressed `.log.gz` (cleanup runs nightly)
- **90+ days**: deleted

Run cleanup manually:
```python
from orb_live.ops.long_term_logging import cleanup_old_logs
from pathlib import Path
cleanup_old_logs(Path("data/logs"))
```

Monthly Markdown reports are generated automatically in `data/archive/{YYYY}/{MM}_review.md`.
